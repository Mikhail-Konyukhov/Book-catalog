# Каталог книг

Тестовое задание: Yii2 + MySQL. CRUD книг и авторов, две роли, подписка гостя
на автора с смс-уведомлением о новой книге, отчёт ТОП-10 авторов за год.

## Запуск

Нужен Docker с Compose v2. PHP и MySQL на хосте не требуются.

```
run.bat        (Windows)
./run.sh       (Linux, macOS)
```

Скрипт поднимает MySQL, ставит зависимости, накатывает миграции, запускает
приложение и проверяет, что оно отвечает. Ненулевой код возврата — на любом
сбое. Приложение: <http://localhost:8080>. Порт занят — `APP_PORT=8088 ./run.sh`.

Демо-учётка: `admin` / `admin123` — заводится миграцией.

## Тесты

```
test.bat       (Windows)
./test.sh      (Linux, macOS)
```

Отдельная база `infotech_test`, обе схемы создаются при первом старте
контейнера MySQL (`docker/init.sql`). Прогоняются наборы Unit и Functional,
код возврата — от Codeception.

## Конфигурация

Только переменные окружения, файлов `*-local.php` нет. Значения по умолчанию
совпадают с `docker-compose.yml`, поэтому из коробки ничего задавать не нужно.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `DB_HOST` | `db` | хост MySQL |
| `DB_NAME` | `infotech` | рабочая база |
| `DB_NAME_TEST` | `infotech_test` | база для тестов |
| `DB_USER` / `DB_PASS` | `root` / `secret` | доступ к MySQL |
| `SMSPILOT_KEY` | пусто | ключ smspilot; пусто — смс не отправляются, факт пишется в лог |
| `APP_PORT` | `8080` | порт на хосте |

Ключа smspilot в репозитории нет и быть не должно. Ключ передаётся через
окружение: `SMSPILOT_KEY=xxx ./run.sh` на Linux и macOS,
`set SMSPILOT_KEY=xxx` перед `run.bat` на Windows.
Без ключа приложение работает целиком, кроме отправки: адресаты считаются,
факт «ключа нет» пишется в лог, `notified_at` остаётся пустым.

Для проверки без реальной отправки подходит ключ-эмулятор smspilot
`XXXXXXXXXXXXYYYYYYYYYYYYZZZZZZZZXXXXXXXXXXXXYYYYYYYYYYYYZZZZZZZZ`:
api отвечает штатным ответом со статусом отправки, смс никуда не уходит,
баланс фиктивный. Отправка и `notified_at` проверены именно на нём.

## Структура

```
components/       SmsSender: отправка смс через smspilot
config/           конфигурация; db.php и params.php читают окружение
controllers/      Book, Author, Subscription, Report, Site
models/           Author, Book, BookSearch, Subscription, ReportForm, User
migrations/       пять миграций: author, book, book_author, subscription, user
views/            вьюхи по контроллерам
tests/            Unit и Functional (Codeception), фикстуры в tests/Support
docker/           init.sql: рабочая и тестовая схемы
```

Страницы: список и карточка книги, список и карточка автора (там же форма
подписки), отчёт `/report/index`, вход `/site/login`. Список и карточки открыты
гостю, создание, редактирование и удаление — только вошедшему пользователю.

## Принятые решения

**Шаблон basic, не advanced.** Ролей две, приложение одно; отдельный backend
добавил бы каркас, которым никто не пользуется.

**Роли — встроенные `?` и `@` в `AccessControl`, без RBAC.** В задании ровно
две роли: гость и аутентифицированный пользователь. `dbManager` с таблицами
прав под такое условие — механика ради механики. Появится третья роль —
переход на RBAC не потребует переписывать контроллеры, только правила фильтра.

**Конфигурация — только переменные окружения.** Файлов `*-local.php` нет:
один механизм вместо двух, и вопрос «что делать с ключом smspilot
в репозитории» снимается — ключа там нет.

**Уведомление вызывается после `save()`, а не в `afterSave()`.** У `Book`
объявлены `transactions()`, поэтому `afterSave()` выполняется внутри
транзакции: HTTP-запрос к smspilot оттуда держал бы её открытой на время
таймаута внешнего сервиса, а откат после успешной отправки уже ничего
не отменит — смс ушла бы про книгу, которой в базе нет.

**Результат отправки виден в базе, а не только в логе.** У подписки есть
`notified_at`: он проставляется тем и только тем строкам, чьи номера ушли
в smspilot. Ошибка отправки не роняет создание книги — книга сохранена,
колонка осталась пустой, и по ней видно, кому смс не дошла. Отправщик ходит
одним POST на всех адресатов сразу и с `CURLOPT_TIMEOUT`: без таймаута
зависший внешний сервис подвешивал бы страницу создания книги.

**Отчёт — один запрос.** `Author::topByYear()` собирает ТОП-10 группировкой
на стороне MySQL, без выборки книг в PHP. Списки книг читают авторов через
`with('authors')`, чтобы не было запроса на строку.

**Телефон нормализуется в `beforeValidate()`.** `8 999 …`, `+7 (999) …`
и `9991234567` приводятся к `+79991234567` до того, как отработает `unique`,
иначе один и тот же номер в разных записях проходил бы валидацию и падал
на уникальном индексе пятисоткой вместо ошибки формы.

## Что сознательно не сделано

- **Отписки нет** — в задании только подписка.
- **Уведомление уходит только при создании книги.** Добавление автора
  к существующей книге смс не порождает.
- **Отправка идёт в цикле HTTP-запроса**, а не через очередь. В бою здесь
  нужен воркер: внешний сервис не должен влиять на время ответа страницы.
- **Регистрации пользователей нет** — пользователь заводится миграцией.
- **Дампа базы нет**, только миграции.
